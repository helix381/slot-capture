# Slot Capture 界面设计稿

状态：供用户确认的视觉与交互方案，尚未替换正式GUI。无需联网即可打开 `prototype/index.html`。

## 用户已确认的方向

- 黑、白、灰为基底；橙红只强调核心数据、当前重点和主操作，不再沿用绿色。
- 背景使用低饱和弥散渐变；内容卡片有充足不透明度，半透明主要放在辅助AI区域。
- 左侧图标＋短文字导航，中间一个区域解决一个任务，右侧放规则识图助手。
- 信息优先级和易读性高于装饰，避免长段说明和多个主按钮。

## 参考与skill

使用GitHub的 [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)，安装在 `E:/AI/skills/ui-ux-pro-max`。

已运行 `desktop analytics dashboard minimal --design-system` 与一次较窄的 `analytics dashboard --design-system`。两次输出的“Enterprise Gateway”营销站布局不适合此本地工作台，因此不采用也不作为验证过的业务布局保存；蓝色方案也不采用，用户的黑白灰＋橙红要求优先。

实际采用的数据库匹配是 Minimalism & Swiss Style 与 Glassmorphism：网格、留白、清楚的文字层级、轻边界、有限的半透明。交互采用语义按钮、可见键盘焦点、拖拽的文件选择替代入口、减少动态效果设置。中文正文字体优先使用系统字体，避免外部字体网络依赖。

参考图取用户提供的低饱和卡片、单色侧栏、辅助区域半透明与留白关系。未将用户原始参考图片放进仓库。

## 页面与状态

1. 连接机台：一个检测主按钮；模拟器、前台游戏、双向心跳三张状态卡；技术详情折叠。连接变化或心跳缺失明确提示原因。
2. 规则档案：Symbol清单与特色玩法分区；协议ID保留“待核对”。示例内容明确标注，勾选核对后才启用保存。
3. 首转核验：开启监听、手动Spin、奖励收尾、审计通过四步；强调首转不混入正式批次。
4. 实时采集：轮数配置、付费进度、Bet、免费次数、累计返奖与事件；未采集时不绘制收益曲线、不生成虚假数值。

顶部“交互设计稿”条属于预览工具，正式应用不保留。连接成功预览仅展示“示例设备／示例前台应用”，不宣称已连接真实设备。侧栏示例档案不会读取或修改真实数据。

图片导入面板支持文件选择、拖放、Ctrl+V、预览、移除、去重，文件只保存在浏览器当前内存；没有服务器和模型调用。所有采集按钮均为明确的交互演示，不启动ADB或游戏。

## 技术边界

正式GUI仍是Tkinter，本稿使用HTML/CSS校准视觉，不能直接将CSS套到现有Tk控件。用户确认后再接入合适的桌面承载方式，沿用现有JSON CLI和采集引擎。此次不迁移框架、不改采集逻辑、不更新EXE或版本号。
